# Shelter Manager G13

A simple web application for organizing the daily work of volunteers in an animal shelter.

The primary goal of this project is to simplify the coordination of dog walks while also providing a lightweight system for managing other recurring daily tasks. The application is intentionally designed to be simple, free to host, and easy to maintain.

## Features

### Volunteer features

- Reserve a dog for a walk.
- Mark a dog as walked.
- Complete items from the daily task list.

### Administrator features

- Add, edit, and remove dogs.
- Create, edit, and remove daily tasks.

### Automatic daily maintenance

The application automatically performs daily housekeeping:

- Clears walk reservations while preserving walk history.
- Displays the number of days since each dog was last walked.
- Resets completed daily tasks.
- Keeps unfinished tasks and shows how many days they have remained incomplete.

## Technology

The application is intentionally built using a minimal, serverless stack:

- **Google Sheets** as the database.
- **Google Apps Script** as the backend.
- **HTML, CSS, and JavaScript** for the frontend.

This approach keeps hosting costs at **zero**, requires virtually no maintenance, and is more than sufficient for a small volunteer team.

## AI-assisted development

This project was created as an experiment in AI-assisted software development.

The implementation was generated through iterative collaboration with **Claude Opus 4.8**, based on my requirements, feature descriptions, and feedback throughout the development process.

The resulting codebase was later refactored and improved with the assistance of **Fable 5**.

While the majority of the code was generated by AI, the application's functionality, workflows, feature set, and design decisions were defined by me. This repository serves both as version control and as the foundation for future development.

## Security

This application is intended for internal use by a single animal shelter.

The administrator PIN is currently hardcoded in the source code. This is an intentional design choice to keep the application as simple as possible.

The system stores no personal or otherwise sensitive information, so implementing a more sophisticated authentication system would add unnecessary complexity for this particular use case.
